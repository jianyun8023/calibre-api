# 混合搜索策略优化

## 问题背景

原有的混合搜索实现存在以下问题：
1. **排序错误**: 使用了错误的比较符号，导致结果排序不正确
2. **策略不佳**: 同时执行语义搜索和关键词搜索，然后使用 RRF (Reciprocal Rank Fusion) 合并结果，但这种方式：
   - 关键词搜索覆盖范围大，可能引入不相关结果
   - RRF 平等对待两种搜索方式，没有充分利用各自优势

## 新的混合搜索策略

### 核心思想

**先召回，后精排**：先用向量搜索召回语义相关的候选集，然后在候选集中用关键词进行精确匹配和重排序。

### 实现流程

```
用户查询 "深度学习入门"
    ↓
1. 语义搜索 (召回阶段)
   - 使用向量相似度搜索
   - 获取 top 100 个语义相关的书籍
   - 确保召回率高，不遗漏相关内容
    ↓
2. 关键词重排序 (精排阶段)
   - 在上述 100 个候选中进行关键词匹配
   - 计算关键词匹配得分
   - 结合语义得分和关键词得分
    ↓
3. 返回最终结果
   - 返回 top 20 个综合得分最高的书籍
```

### 评分机制

#### 1. 语义得分 (40% 权重)
- 由向量相似度计算得出
- 范围: 0-1
- 优势: 理解语义，召回相关内容

#### 2. 关键词得分 (60% 权重)
- 多维度匹配计算
- 范围: 0-1
- 优势: 精确匹配，提高准确率

#### 3. 关键词匹配详细规则

**完整查询匹配** (权重最高):
- 标题完全匹配: 10 分
- 作者完全匹配: 8 分
- 出版社完全匹配: 6 分
- 标签完全匹配: 5 分
- 简介完全匹配: 3 分

**单个关键词匹配** (每个关键词最多 5 分):
- 标题包含: 3.0 分
- 作者包含: 1.5 分
- 出版社包含: 1.0 分
- 标签包含: 0.8 分
- 简介包含: 0.3 分

**最终得分计算**:
```
final_score = semantic_score × 0.4 + keyword_score × 0.6
```

## 优势对比

### 旧策略 (RRF 融合)
```
❌ 问题:
- 关键词搜索可能返回大量不相关结果
- RRF 平等对待两种搜索，没有层次
- 计算复杂度高 (两次独立搜索)
- 结果可能偏向关键词匹配，忽视语义相关性
```

### 新策略 (先召回后精排)
```
✅ 优势:
- 语义搜索保证召回率，不会遗漏相关内容
- 关键词匹配提高精确度，优先推荐精确匹配
- 两阶段策略清晰，各司其职
- 计算效率高 (只在候选集中进行关键词匹配)
- 更符合人类搜索心理模型
```

## 参数调优

### 候选集大小
```go
semanticLimit := limit * 3  // 默认 3 倍
if semanticLimit < 100 {
    semanticLimit = 100     // 最小 100
}
```

**建议**:
- 小结果集 (limit ≤ 10): 使用 100 个候选
- 中等结果集 (10 < limit ≤ 50): 使用 3 倍候选
- 大结果集 (limit > 50): 使用 2 倍候选

### 权重调整

**当前配置** (适用于大多数场景):
- 语义得分: 40%
- 关键词得分: 60%

**可调整场景**:

1. **更重视精确匹配**:
   ```go
   finalScore = semanticScore * 0.3 + keywordScore * 0.7
   ```

2. **更重视语义理解**:
   ```go
   finalScore = semanticScore * 0.5 + keywordScore * 0.5
   ```

3. **纯关键词模式**:
   ```go
   finalScore = semanticScore * 0.2 + keywordScore * 0.8
   ```

## 性能优化

### 时间复杂度
- **旧策略**: O(n₁) + O(n₂) + O((n₁+n₂)log(n₁+n₂))
  - n₁: 语义搜索结果数
  - n₂: 关键词搜索结果数
  
- **新策略**: O(n) + O(n×m) + O(n×logn)
  - n: 语义候选集大小 (100)
  - m: 平均关键词数量 (2-5)
  
**结论**: 新策略在大多数情况下更快

### 空间复杂度
- **旧策略**: O(n₁ + n₂)
- **新策略**: O(n)

**结论**: 新策略内存占用更少

## API 使用

### 使用混合搜索

```bash
# GET 请求
curl "http://localhost:8080/api/search?q=Python机器学习&mode=hybrid&limit=20"

# POST 请求
curl -X POST "http://localhost:8080/api/search" \
  -H "Content-Type: application/json" \
  -d '{
    "q": "Python机器学习",
    "mode": "hybrid",
    "limit": 20
  }'
```

### 搜索模式对比

1. **keyword** - 纯关键词搜索
   ```bash
   curl "http://localhost:8080/api/search?q=Python&mode=keyword"
   ```
   - 速度最快
   - 精确匹配
   - 可能遗漏语义相关内容

2. **semantic** - 纯语义搜索
   ```bash
   curl "http://localhost:8080/api/search?q=机器学习入门书籍&mode=semantic"
   ```
   - 理解语义
   - 召回率高
   - 可能包含不太精确的结果

3. **hybrid** - 混合搜索 (推荐)
   ```bash
   curl "http://localhost:8080/api/search?q=Python机器学习&mode=hybrid"
   ```
   - 兼顾召回率和精确度
   - 最佳用户体验
   - 推荐作为默认模式
