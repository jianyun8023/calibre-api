## 🔒 安全原则

MCP (Model Context Protocol) 工具设计遵循 **只读优先** 原则，确保 AI 助手只能读取和搜索数据，**不能修改或删除用户的书籍库**。

### 为什么这么设计？

1. **防止误操作**: AI 可能误解用户意图，执行错误的删除/修改操作
2. **不可逆风险**: 删除书籍、修改元数据等操作难以撤销
3. **用户控制**: 重要操作应该由用户通过 Web UI 明确确认
4. **审计追踪**: Web UI 可以提供更好的操作日志和确认流程

## ✅ 已注册的安全工具

以下工具均为 **只读操作**，不会修改任何数据：

### 1. 搜索工具

#### `search_books`
- **功能**: 搜索书籍（关键词 + 语义搜索）
- **参数**: 
  - `query` (必需): 搜索关键词
  - `filter`: 过滤器类型（title/author/publisher/isbn/tags）
  - `limit`: 返回数量
  - `offset`: 分页偏移
- **安全性**: ✅ 只读查询，无副作用

### 2. 书籍详情工具

#### `get_book`
- **功能**: 获取单本书籍的详细信息
- **参数**: 
  - `id` (必需): 书籍 ID
- **安全性**: ✅ 只读查询，无副作用

### 3. 推荐工具

#### `random_books`
- **功能**: 随机推荐书籍
- **参数**: 
  - `limit`: 返回数量（默认10）
- **安全性**: ✅ 只读查询，无副作用

#### `recent_books`
- **功能**: 获取最近添加/更新的书籍
- **参数**: 
  - `limit`: 返回数量（默认20）
  - `offset`: 分页偏移
- **安全性**: ✅ 只读查询，无副作用

### 4. 元数据工具

#### `get_isbn_metadata`
- **功能**: 根据 ISBN 查询豆瓣元数据
- **参数**: 
  - `isbn` (必需): ISBN-10 或 ISBN-13
- **安全性**: ✅ 只读查询，调用外部 API，不修改本地数据

#### `search_metadata`
- **功能**: 在豆瓣搜索书籍元数据
- **参数**: 
  - `title` (必需): 书名
  - `author`: 作者（可选）
- **安全性**: ✅ 只读查询，调用外部 API，不修改本地数据

## ❌ 已移除的危险工具

以下工具 **已被移除**，不会通过 MCP 暴露给 AI：

### `update_book_metadata` (已移除)
- **原因**: 修改元数据可能导致数据不一致或丢失
- **替代方案**: 用户通过 Web UI 手动编辑
- **Web UI 路径**: `/books/:id` → 编辑按钮

### `delete_book` (已移除)
- **原因**: 删除操作不可逆，风险极高
- **替代方案**: 用户通过 Web UI 手动删除（需确认）
- **Web UI 路径**: `/books/:id` → 删除按钮 → 确认对话框

## 🎯 使用场景

### ✅ AI 可以帮你做的事

1. **发现书籍**
   - "帮我找关于 Go 语言的书"
   - "推荐几本技术书籍"
   - "最近添加了哪些新书？"

2. **获取详情**
   - "这本书的作者是谁？"
   - "给我看看《Go 语言实战》的详细信息"
   - "这本书的 ISBN 是什么？"

3. **元数据查询**
   - "查询 ISBN 9787111558422 的书籍信息"
   - "在豆瓣搜索《深入理解计算机系统》"

### ❌ AI 不能帮你做的事

1. **修改元数据**
   - ❌ "把这本书的作者改成张三"
   - ✅ 请通过 Web UI 手动修改

2. **删除书籍**
   - ❌ "删除 ID 为 123 的书"
   - ✅ 请通过 Web UI 手动删除

3. **批量操作**
   - ❌ "批量修改所有 Python 书籍的标签"
   - ✅ 请通过 Web UI 批量操作功能

## 🔐 安全最佳实践

### 对于开发者

1. **新增工具前评估风险**
   - 工具是否修改数据？
   - 操作是否可逆？
   - 是否需要用户确认？

2. **使用工具描述说明安全性**
   ```go
   Description: "根据书籍 ID 获取详细信息。此操作为只读操作，不会修改任何数据。"
   ```

3. **在代码注释中标注安全级别**
   ```go
   // get_book - 获取书籍详情（只读，安全）
   // update_book_metadata - 已移除（危险操作）
   ```

### 对于用户

1. **了解 AI 的能力边界**
   - AI 只能搜索和查询，不能修改数据
   - 重要操作需要通过 Web UI 完成

2. **使用 MCP Inspector 测试**
   - 查看可用工具列表
   - 验证没有危险工具暴露

3. **定期备份数据**
   - Calibre 数据库定期备份
   - 防止意外数据丢失

## 📊 设计决策记录

### 为什么不实现"需要确认"的修改工具？

**考虑过的方案**:
- 方案 A: 修改工具需要用户输入 `confirm: true` 参数
- 方案 B: 修改工具返回确认链接，用户点击后执行
- 方案 C: 完全移除修改工具（✅ 已采用）

**选择方案 C 的原因**:
1. **用户体验**: Web UI 提供了更好的可视化确认流程
2. **操作审计**: Web UI 可以记录完整的操作日志
3. **简化架构**: MCP 专注于只读查询，职责清晰
4. **降低风险**: 从源头杜绝误操作可能性
